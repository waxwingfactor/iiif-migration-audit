# Discovery report: cultural heritage / accessibility

Research date: 2026-10-15. Scope: public evidence and competitor documentation; no user interviews or outreach. Search absence is not proof that no competitor exists. Primary sources receive priority. Recommendation is conditional on the root's independent comparison with other candidates.

## Candidate A — IIIF migration and release regression audit (best candidate here)

**Exact beachhead:** the engineer responsible for an academic or independent cultural-heritage library's IIIF Presentation manifest generator, working with a collections librarian, while replacing a repository/generator or moving Presentation 2.1 output to 3.0. They have old and candidate JSON exports or URL lists, and need evidence that a technically valid release has not lost collection meaning.

**Job:** before switching the public viewer or generator, find lost/reordered pages, missing multilingual descriptions or metadata, changed rights/attribution, changed canonical Canvas IDs that strand annotations, broken range membership, and omitted OCR/annotation links; distinguish intentional URI rewrites and expected version shape changes from actual content loss. Produce a reviewable audit and a CI result.

### Pain evidence, with limits

- [IIIF Commons parser issue 39](https://github.com/IIIF-Commons/parser/issues/39), opened **2024-06-19**, remains open in the GitHub API at research time. A mixed `description` array containing a plain string and an English language value loses the plain string in an upgrade. This is an especially useful deterministic fixture. **Do not claim the latest package reproduces this until tested**; open issues can lag implementation.
- [Parser issue 40](https://github.com/IIIF-Commons/parser/issues/40), opened **2024-06-19**, reports that a string `seeAlso` fails to obtain the correct ID during upgrading. Same current-behavior caveat.
- [Parser issue 52](https://github.com/IIIF-Commons/parser/issues/52), opened **2025-06-07**, cites Tify's implementation: provider label is empty and `related` is handled incorrectly in conversion. Same current-behavior caveat. These are maintainer issues, not three independent institutional customers.
- [University of Leeds Libraries, Open Content Migration Completed](https://leedsunilibrary.wordpress.com/2026/03/27/open-content-migration-completed/), **2026-03-27**: migration involved approximately 400,000 open files; the team developed a testing/review/rights-normalization framework and a temporary Flask migration dashboard. This is direct institutional evidence for migration verification effort, although it is broader than v2-to-v3 conversion.
- [IIIF cookbook, publishing v2 and v3 at the same URL](https://iiif.io/api/cookbook/recipe/0057-publishing-v2-and-v3/), undated: describes content negotiation and explains why new resource locations can break annotations made by third parties. This makes identifier continuity a real user outcome rather than a JSON-format preference.
- [Digital Scriptorium 2022 annual meeting minutes](https://digital-scriptorium.org/wp-content/uploads/2023/04/2022-Annual-Meeting-Minutes.pdf), meeting **2022**, published path **2023-04**: explicitly describes checking that data was not lost in a repository migration, preserving legacy exports and hosting images through Internet Archive/IIIF. Broad migration pain, not a specific request for this product.
- [Cecília Pitta IIIF adopter study](https://run.unl.pt/bitstream/10362/154579/1/Cecilia_Pitta_versao_revista_2023.pdf), **2023**: qualitative adopter interviews identify lack of knowledgeable resources for content migration and its validation as a risk. Useful supporting evidence; limited sample and older than the new tooling.

**3. Inspect schema/semantics and an adversarial implementation counterargument.** [Official Presentation 3 change log](https://iiif.io/api/presentation/3.0/change-log/) confirms that the transition includes semantics, not just renamed keys: descriptions can move to summary or metadata; related links acquire more specific homepage semantics; language maps change; Sequences are removed; ranges change representation. A JSON diff is therefore noisy, and blindly upgrading both inputs through one converter could hide the same lossy conversion on both sides.

The defensible design is **independent version-specific fact extraction with provenance pointers and explicit unsupported-coverage diagnostics**. Preserve source text and identities, compare named invariants, and require explicit opt-in mappings for renamed resources. Do not guess Canvas correspondence by page position alone: a missing page can shift every subsequent page. Exact ID and configured rewrite mapping should outrank image-service identity; ambiguous matches require human review. Never report a clean audit when an unhandled structure or extension could conceal lost content.

### Alternatives and positioning

- **Market alternative:** engineer scripts plus spreadsheet/manual spot checks in Mirador/Universal Viewer; schema validation; visual review of raw JSON differences.
- **Strongest product alternative:** IIIF Commons parser plus a general JSON diff (with official validator for conformance). This is available, free, and familiar, so the product must prove value beyond a wrapper.
- **Whole product:** local import of two documents or batch pairs; independent extraction; predictable ID remapping policy; source-linked loss findings; explicit unmatched/unsupported data; stable HTML/JSON/CSV reports; filterable reviewer UI; saved approval/baseline files; nonzero CI exits; example migrations; exhaustive adversarial fixtures and ordinary-user documentation. Optional remote fetch should remain separate from offline comparison because network and CORS observations are not semantic proof.
- **Two-sentence positioning:** For digital-library engineers replacing IIIF manifest generators who are dissatisfied with manual viewer spot checks and noisy JSON diffs, [name] is a migration audit workbench that reveals lost pages, metadata, rights, and annotation identities before a collection release. Unlike IIIF conversion and conformance libraries, it compares independently generated source and candidate collections through traceable preservation checks, explicit ID mappings, reviewer decisions, and reproducible CI reports.

### Scenarios

1. A librarian checks a bilingual book release. Both manifests validate, but the candidate retains English while losing an untagged description. The audit identifies the exact lost source value and JSON pointer instead of a large syntactic diff.
2. A repository host changes. Expected service URLs move from old to new host, but Canvas IDs must remain stable for external researchers' annotations. A configured image-service mapping suppresses expected image URL churn while Canvas identity changes remain blockers.
3. A generator optimization accidentally sorts page labels lexically: 1, 10, 11, 2. The before/after audit shows ordering changes and affected ranges, while structural validation still passes.

### Feasibility and unresolved risk

Feasible without paid AI/backend: deterministic JSON processing in a shared TypeScript core, browser UI plus Node CLI, static deploy, fixture-based tests. File imports can remain local. A meaningful complete first release needs a candid supported subset; AV, arbitrary JSON-LD extensions, remote ranges/annotation pages, and multiple old sequences must be handled or explicitly marked incomplete. There is **no direct customer validation yet**. Evidence supports a narrow, poorly assembled workflow, not a claim that no one has solved it privately or that a large market exists. Parent should run one more independent counter-search and practical competitor comparison before committing.

## Candidate B — metadata-to-scan batch reconciliation for student-run library digitization (real pain, weaker novelty)

**Beachhead:** small college special-collections digitization labs using undergraduate workers, Excel metadata, folders of JPEG/PDF scans, and Archipelago or a similar ingest system.

[Union College case study](https://journal.code4lib.org/articles/18340), **2025-04-14**, reports a concrete workflow and outcome: filename/metadata mismatches, page-count errors, duplicate identifiers, and misplaced files escaped manual QC. In its test, 32% of records marked scanned could not be found; each manual search took approximately two minutes. They built a Python/Openpyxl desktop checker, publishing [QualityControlAutomation](https://github.com/schaffer-library/QualityControlAutomation). Its folder/page-count assumptions are highly local, suggesting an opportunity for configurable profiles rather than institution-specific scripts. This is particularly good pain evidence because authors are actual practitioners describing actual failures.

**Market alternative:** student-by-student file search and spreadsheet checks. **Product alternative:** their published app, plus [Goobi workflow's QA tooling](https://docs.goobi.io/en/browse?filter=Goobi+workflow), Kitodo, and custom OpenRefine/scripts. A general library batch QC workbench could provide reusable profiles, filesystem-safe matching, page counts, contact sheets, immutable reports and annotated workbook copies. However, much of this would improve packaging and configuration around existing software. Generic scan QA also has [Matchbox](https://staging.openpreservation.org/blogs/matchbox-toolset-webcast/) (**2013-06-20**), an established open toolset for image-version comparison and duplicate-page detection without OCR. Reject for the user's stronger novelty requirement unless other candidates fail; contributing configurable profiles to existing software might be the better action.

## Candidate C — audio-description narration gap/collision workbench (reject without much stronger evidence)

**Beachhead considered:** independent accessibility describers supplying prerecorded narration clips for short films, needing collision-free placement between dialogue.

The task is concrete and deterministic, but a [local Audio Description Editor](https://teck-tani.com/en/audio-description-editor) already provides manually protected dialogue windows, cue recordings/imports, collision/boundary warnings, mixing and WAV/JSON/CSV export. It has severe short-clip limits, but extending scale would not establish a unique need by itself. Academic [Rescribe](https://arxiv.org/abs/2010.03667), **2020-10-07**, goes further into authoring/refining descriptions and scheduling narration. No strong primary practitioner pain evidence for an overlooked full workflow was found in this pass. Also ordinary caption validation is heavily saturated. Do not pursue as a new product merely because it is an accessibility niche.
